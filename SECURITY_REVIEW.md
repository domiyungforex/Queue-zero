# QueueZero security review — 2026-10-02

Scope: authenticated business workspace, public queue/ticket flows, staff operations, realtime, notification delivery, billing and deployment. This is an engineering review, not independent penetration testing.

| Area / issue | Severity | Implemented protection | Remaining risk / verification |
| --- | --- | --- | --- |
| Tenant isolation and staff assignment | Critical | Clerk authentication at server boundaries; current membership derived server-side; forced RLS; RPCs authorize independently; post-lock membership and assignment checks for queue operations. | Hosted identity flow must be checked with real accounts after configuration. |
| Concurrent calls, retries and invalid transitions | Critical | Queue locks; one-serving constraint; FIFO ordering; actor-bound request records; transition guards; audit writes in the same transaction. | Retain request history. Never delete it as routine cleanup. |
| Browser payment redirect falsely activating plan | Critical | Provider transaction verification against stored reference, amount, currency and plan; activation RPC is service-role only. | Paystack credentials and real test-mode transactions required before selling subscriptions. |
| Forged, duplicate or delayed webhooks | High | SHA-512 signature over raw body; constant-time comparison; stable event IDs; transactional processing; current provider state for subscription events; ambiguous tenant mapping fails closed. | Provider reconciliation and real subscription renewal/cancellation tests remain operational requirements. |
| Public ticket privacy | High | UUID bearer capabilities; strict allowlisted projections; no names, phones or internal IDs on public ticket/display APIs; no indexing/referrers; service worker never caches ticket pages. | Anyone possessing a ticket URL has that ticket's customer capabilities. |
| Push endpoint SSRF | High | HTTPS-only known browser push provider hosts; reject credentials, local hosts and nonstandard ports; bounded subscription count and input sizes. | Additional push providers require explicit allowlisting and review. |
| Realtime data leakage | High | Private Broadcast channels; receive-only policies; tenant/assignment checks for staff topics; opaque customer topics; payloads contain only invalidations. | Topic token is a bearer capability. Polling and reconnect fetches retain source-of-truth behavior if events are lost. |
| Administrative mutations | High | Role checks in server actions and SQL; staff assignment and removal audit; owner-only business/billing changes; foreign IDs rejected. | Do not share owner accounts between employees. |
| Public join abuse | Medium | Transactional network rate limits, HMAC browser keys, idempotency aliases, queue capacity guard, UUID request IDs. | Cookie clearing and distributed networks are not proof of identity; tune from pilot evidence. |
| Notification failure | Medium | Transactional outbox, leased claims, bounded attempts/backoff, dead-endpoint removal, notification tags; provider failure does not roll back queue state. | External delivery is at-least-once, not exactly-once. Vercel daily cron is a recovery fallback; actions trigger immediate processing. Monitor pending jobs and use a more frequent worker for larger traffic. |
| XSS / CSRF / framing | Medium | React text rendering, validated inputs/URLs, Next server-action origin protections, explicit push registration origin check, signature-protected webhook, nosniff/frame-denial headers. | Review any future HTML/third-party embed feature separately. |
| Secrets and logs | High | Server-only service clients; ignored environment file; production variables stored in Vercel; no payment payloads or full provider errors in logs. | Credentials shared in chat should be rotated before a real-business pilot. |
| Offline stale state | Medium | Only generic offline document cached. Authoritative state refetched after reconnect and tab focus; failed connections are visible. | Offline customers must speak to staff if their turn is near. |

Validation includes TypeScript/lint, application tests, PostgreSQL role/state/concurrency tests, browser viewport checks, and deployment smoke tests. Counts and final hosted results are recorded in PRODUCTION_CHECKLIST.md. Physical-phone checks cannot be replaced by desktop browser emulation.
